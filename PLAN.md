# План: сервіс лояльності поверх Syrve

Syrve Loyalty — джерело істини (гості, картки, баланси, транзакції). Наш сервіс — тонка обгортка: бот, адмін-панель, сповіщення. У своїй БД зберігаємо лише те, чого немає в Syrve.

## 1. Стек

- **Node.js 20 + TypeScript**, монорепо (npm workspaces): `apps/api`, `apps/admin`
- **Fastify** — API, віддача зібраної адмінки, життєвий цикл бота і worker (плагіни, TypeBox-схеми, pino-логи, `inject()` для тестів)
- **grammY** — Telegram-бот, long polling (без домену й HTTPS)
- **Nuxt 3 + Vue 3 + TS** — адмін-панель ; **Nuxt UI** (українська локаль `uk`). Режим SPA (`ssr: false`), збірка через `nuxt generate` у статику, яку віддає Fastify — окремий Node-сервер для фронту не потрібен
- **Postgres 17 + Prisma** — міграції через `prisma migrate deploy`, запускаються на старті контейнера
- **Vitest** — тести; **bcryptjs** — паролі; **qrcode** — QR
- **Docker**: multi-stage Dockerfile, compose = `db` + `app`; запуск `docker compose up`

## 2. Архітектура

```
Telegram ⇄ grammY ─┐
Nuxt (SPA) ⇄ REST ────┼─> services ─> SyrveClient ─┬─ Real (токен з автооновленням)
Worker (polling) ──┘       │
                           └─> Postgres
```

- **У нашій БД**: `guests` (telegram_id, phone, syrve_customer_id, card), `admin_users`, `bonus_operations` (журнал), `sync_state` (остання revision), `processed_transactions` (унікальний id), `notifications` (outbox).
- **З Syrve**: баланс, картки, програма, транзакції. Баланс не кешуємо.

## 3. Ключові рішення

1. **Секрети** (apiLogin, токен бота) — лише в `.env` + `.env.example`; репозиторій публічний.
2. **Токен Syrve**: кеш, оновлення до спливу, retry на 401, один refresh одночасно.
3. **Дублі гостя**: телефон у форматі +380…, пошук у Syrve перед створенням, UNIQUE у БД.
4. **Списання**: перевірка балансу, сума > 0, запис операції `pending → done/failed`.
5. **Сповіщення (О6)**: надсилає лише worker за транзакціями `by_revision`; дедуп по id транзакції; outbox; на першому запуску baseline (стару історію не розсилаємо).
6. **Syrve**: працюємо лише з реальним Syrve (тестова організація). Режимів real/mock немає, `SyrveClient` має одну реалізацію — `RealSyrveClient`.
7. **Адмінка**: cookie-сесія (httpOnly), rate-limit на вхід, CSRF, сид адміна з env.

## 4. Функціонал адмін-панелі

- Вхід за логіном/паролем, усе інше під guard
- Пошук гостя за телефоном: ім'я, картка, баланс
- Картка гостя: «Нарахувати»/«Списати» з обов'язковою причиною
- Журнал операцій
- За вибором: таблиця гостей (Д2), історія (Д1), статистика (Д9)
