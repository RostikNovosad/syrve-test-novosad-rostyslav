# Сервіс лояльності для кафе й ресторанів (поверх Syrve)

Прототип: гість реєструється в Telegram-боті й отримує бонусну картку з QR та балансом, адміністратор закладу керує гостями й бонусами у веб-панелі. Гості, картки, програми, баланси й транзакції живуть у **Syrve Loyalty**; наш сервіс — «обгортка» над Syrve Cloud API (бот, панель, сповіщення). Працює з тестовою організацією Syrve. Інтерфейс — українською.

Архітектура — в [ARCHITECTURE.md](ARCHITECTURE.md), підсумок виконаного — в [summary.md](summary.md).

## Що потрібно

- Docker з Docker Compose
- `apiLogin` тестової організації Syrve
- Токен Telegram-бота від [@BotFather](https://t.me/BotFather)

## Запуск (одна команда)

```bash
cp .env.example .env
```

У `.env` заповніть два значення:

| Змінна               | Що це                                      |
| -------------------- | ------------------------------------------ |
| `SYRVE_API_LOGIN`    | ключ `apiLogin` тестової організації Syrve |
| `TELEGRAM_BOT_TOKEN` | токен бота від @BotFather                  |

Рекомендовано також задати `SESSION_SECRET` (`openssl rand -hex 32`); без нього використовується випадковий, і після рестарту сесії в панелі скидаються. Усе інше має робочі значення за замовчуванням.

```bash
docker compose up --build
```

Піднімаються два контейнери: `db` (Postgres 17) і `app` (бот, API, worker і зібрана адмінка в одному процесі). На старті `app` сам застосовує міграції (`prisma migrate deploy`), створює початкових користувачів панелі й знаходить в Syrve організацію та програму лояльності. Готовність видно в логах:

```
Syrve готовий: організація …, програма …
Telegram-бот @… запущено
Worker транзакцій запущено (кожні 20 с)
Server listening at http://0.0.0.0:3000
```

Адреси:

| Що                                                 | Адреса                             |
| -------------------------------------------------- | ---------------------------------- |
| Лендінг                                            | http://localhost:3000/             |
| Адмін-панель                                       | http://localhost:3000/admin        |
| Перевірка БД                                       | http://localhost:3000/health       |
| Перевірка звʼязку з Syrve (організація + програма) | http://localhost:3000/health/syrve |
| Swagger API панелі                                 | http://localhost:3000/docs         |

### Початкові дані (сиди)

Створюються автоматично на старті з `.env` (значення з `.env.example`):

| Роль     | Логін   | Пароль  | Доступ                                                 |
| -------- | ------- | ------- | ------------------------------------------------------ |
| Власник  | `admin` | `admin` | усе: гості, журнал, статистика, працівники, журнал дій |
| Менеджер | `user`  | `user`  | гості й журнал операцій                                |

Власник з `ADMIN_LOGIN` / `ADMIN_PASSWORD` оновлюється при кожному старті. Менеджер з `SEED_MANAGER_*` створюється лише якщо такого логіну ще немає (щоб не скидати зміни, зроблені у панелі). Якщо не потрібен — залиште `SEED_MANAGER_*` порожніми.

### Зупинка і скидання

```bash
docker compose down        # зупинити, дані збережуться
docker compose down -v     # зупинити й видалити БД
```

## Як перевірити основні функції

Заздалегідь: сервіс запущено, у Telegram відкрито вашого бота, у панелі виконано вхід (`admin` / `admin`).

### О1. Підключення до Syrve

1. Відкрийте http://localhost:3000/health/syrve — у відповіді `"status":"ok"`, організація й програма лояльності.
2. У логах `app` є рядок `Syrve готовий: організація …, програма …`.
3. Ключ береться лише з `.env`; токен Syrve кешується, оновлюється до спливу (1 година) і перевипускається при 401 (покрито тестами).

### О2. Реєстрація в Telegram

1. У боті натисніть `/start` → кнопка «📱 Поділитися номером».
2. Бот просить імʼя — введіть його.
3. Бот створює гостя в Syrve, підключає до програми, випускає картку й показує її.
4. Дублі: повторний `/start` того ж акаунта показує наявну картку; той самий номер, що вже привʼязаний до іншого акаунта, бот відхиляє. Гість, якого раніше створив адмін у панелі за тим самим номером, привʼязується до свого запису без дубля.

Приймаються лише українські номери (`+380…`, `050…`, `380…` — усе нормалізується до `+380XXXXXXXXX`). Контакт має належати самому користувачу.

### О3. Картка, QR і баланс у боті

Кнопка «💳 Моя картка» (або `/card`) надсилає QR-код з номером картки й підпис з номером та балансом. Баланс щоразу читається з Syrve, не кешується.

### О4. Адмін-панель: вхід і пошук гостя

1. http://localhost:3000/admin → вхід `admin` / `admin`. Сесія — httpOnly cookie; після 5 невдалих спроб за хвилину вхід тимчасово блокується.
2. Розділ «Гості» → пошук за телефоном (`050 123 45 67`, `+380501234567`) або за імʼям.
3. Картка гостя показує імʼя, телефон, номер картки, баланс (з Syrve) і чи підключений Telegram.

Гості, створені безпосередньо в кабінеті Syrve, потрапляють у наш список при першому відкритті за номером.

### О5. Ручне нарахування й списання

1. Картка гостя → «Нарахувати» або «Списати» → сума й обовʼязкова причина (від 3 символів).
2. Баланс у картці оновлюється одразу; перевірити можна й у боті («Моя картка»).
3. Спроба списати більше за баланс відхиляється повідомленням «Недостатньо бонусів…». Сума має бути більшою за нуль.
4. Розділ «Журнал»: хто, коли, кому, скільки, чому, статус (`done` / `failed`). Журнал гостя також є на його сторінці.

### О6. Сповіщення в Telegram про зміну балансу

1. Гість має бути зареєстрований у боті.
2. Нарахуйте або спишіть бонуси **з панелі** (О5) — або змініть баланс у **кабінеті Syrve Loyalty**.
3. Протягом ~20 секунд (`NOTIFY_INTERVAL_SECONDS`) бот надішле повідомлення:
   ```
   Нараховано бонусів: 50
   Баланс: 120
   ```
4. Одна операція — одне повідомлення, незалежно від того, звідки вона зроблена: надсилає лише worker, дедуплікація за id транзакції (покрито тестами). Стара історія гостя при першому проході не розсилається.

## Додаткові функції

|                                       | Де                        | Що                                                                                                                                                                     |
| ------------------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Д1. Історія операцій                  | «Журнал» і сторінка гостя | усі ручні операції з фільтром по гостю                                                                                                                                 |
| Д2. Список гостей                     | «Гості»                   | пошук, фільтри (є Telegram / є картка / дата реєстрації), сортування, пагінація, створення й редагування гостя (імʼя й телефон змінюються і в Syrve)                   |
| Д9. Статистика (лише власник)         | «Статистика»              | за період: гості (усього, нові, з Telegram), нараховано/списано за всіма транзакціями гаманця Syrve, графік по днях                                                    |
| Д10. Ролі й журнал дій (лише власник) | «Працівники»              | створення/вимкнення/видалення працівників, ролі `власник` / `менеджер`, журнал дій (входи, зміни гостей і працівників). Не можна лишити систему без активного власника |

Для перевірки ролей увійдіть як `user` / `user`: розділи «Статистика» й «Працівники» недоступні.

## Тести

```bash
npm ci
npm run test        # 85 тестів (Vitest), БД і Syrve не потрібні
npm run typecheck -w apps/api
```

Тести покривають токен Syrve (кеш, 401-retry, один refresh), реєстрацію без дублів, операції (ліміти, недостатньо балансу, pending → done/failed), worker сповіщень (дедуп, baseline, повтори, blocked), ролі, пошук і статистику.

## Розробка без Docker для застосунку

```bash
docker compose up -d db        # лише база, порт 5433
# у .env розкоментуйте DATABASE_URL=postgresql://loyalty:change-me@localhost:5433/loyalty?schema=public
npm ci
npm run migrate:deploy -w apps/api
npm run dev                    # API + бот + worker на :3000
npm run dev:admin              # Nuxt dev на :3001 з проксі /api → :3000
```

Зміни схеми БД — лише через міграції: `npm run migrate:dev -w apps/api`.

## Структура

```
apps/api     Fastify + grammY + worker, Prisma (схема й міграції в prisma/)
apps/admin   Nuxt 3 SPA: лендінг (/) і панель (/admin), збирається в статику
docs/        нотатки про Syrve Cloud API
```
